# What a customer needs from a release

Judgment only; the templates set the layout, and the checks set the limits.

1. Start with the change the reader will notice, in the words they use for their own work.
2. Say what it affects: which accounts, workflows or reports. Leave out internal components.
3. State action explicitly: "No action is needed" when none is; otherwise the one step, and by when.
4. Give the ship date exactly as the release notes state it. Never estimate one.
5. Keep internal-only items (spikes, refactors, known risks, support runbooks) out of the customer message.
6. Mention a change only when the notes describe it; do not infer a benefit they do not claim.
